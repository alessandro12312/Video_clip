## Sfide

### 1. Bug critico setQueriesData — trovato in verifica Playwright
`setQueriesData({ queryKey: ["videos"] })` nell'`onMutate` di `useLikeVideo`/`useUnlikeVideo` faceva match con TUTTE le query che iniziano con `["videos"]`, incluse cache detail (`Video`) e popup-comments (`Comment[]`) che non hanno `.pages`. Chiamata `updateVideoInPages(undefined, ...)` → `TypeError: undefined.map()` → mutation bloccata prima della POST.

**Fix:** Aggiunto guard `if (!old || !('pages' in old) || !Array.isArray(old.pages)) return old` nel callback `setQueriesData`.

**Lezione:** `setQueriesData` con query key ampia e' pericoloso — serve SEMPRE un type guard sulla struttura dati. Un test frontend del mutation hook avrebbe catturato questo bug.

### 2. Zero test frontend — debito crescente
Confermato anche in Epic 3: nessun test Jest/Vitest per componenti nuovi. CardAsPlayer, double-tap, popup overlay, marker, useMarkerComments — tutti senza test automatizzati.

### 3. Action items retro precedenti — nessuno completato
Su 6 action items dalla retro Epic Intermedio, **zero completati**. CI, test frontend, PRD, Playwright, ClipCard.tsx — tutti rimandati. Pattern di negligenza sui fondamentali.

### 4. Test rotto pre-esistente mai fixato
`test_registration_assigns_toconfirm_group` menzionato in tutte e 5 le story come "non correlato" — il gruppo `toconfirm` non viene creato tramite data migration nel DB di test. Da fixare.

## Pattern Identificati

### Pattern positivi (da ripetere)
1. **@action con methods multipli** — `["post", "delete"]` con branching su `request.method` per like/unlike
2. **Annotazioni Count(distinct=True) + Exists()** — pattern standard per contatori e booleani per-utente
3. **Optimistic update con snapshot/rollback** — `onMutate` → snapshot → update cache → `onError` rollback → `onSettled` invalidate
4. **Gestione silente 409** — like duplicato ignorato senza rollback ne' errore utente
5. **Hook condiviso per logica duplicata** — `useMarkerComments` estratto in review (DRY)
6. **Endpoint non-paginato per dati limitati** — popup-comments come lista piatta (max ~durata_video commenti)
7. **Guard clause su edge case** — `desempate_ponderato()` con return early per lista vuota/singola

### Pattern da migliorare
1. **Type guard su setQueriesData** — SEMPRE verificare struttura dati quando la query key e' ampia
2. **Test frontend** — zero test per 5 epic consecutive
3. **Follow-through action items retro** — sistema di tracking mancante
4. **Test rotti** — fixare immediatamente, non marcare come "non correlato"
