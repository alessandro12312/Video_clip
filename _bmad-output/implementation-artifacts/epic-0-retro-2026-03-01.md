## Sfide

### 1. Brownfield Surprises (3/4 story)
Il codebase ereditato dal repo Skikky/Video_clip aveva problemi nascosti:
- `requirements.txt` codificato UTF-16 LE (Story 0-1)
- `test_spareggio.py` con ImportError pre-esistente (Story 0-2)
- `error_handler.py` con firma errata: 1 argomento, DRF ne passa 2 (Story 0-3)

**Lezione:** Un codebase brownfield richiede una fase di "discovery" implicita durante lo sviluppo. Non tutti i bug sono visibili prima di toccare il codice.

### 2. Code Review Findings Volume (24 in 4 story)
La media di 6 findings per story e alta. I tipi piu comuni:
- **Completeness** (File List incomplete, docstring imprecise)
- **Test accuracy** (test che passano per il motivo sbagliato)
- **Dependency assumptions** (versioni non verificate)

**Lezione:** Ridurre i findings richiede migliori checklist pre-commit e verifica versioni upfront.

### 3. Dependency Version Friction (2/4 story)
- jsdom v27 incompatibile con Node.js 20.18.1 → downgrade a v26
- @tanstack/react-query-devtools non bundled con react-query → installazione separata

**Lezione:** Verificare le dipendenze con `npm ls` o `pip show` prima di assumere compatibilita.

### 4. CI non verificata end-to-end
La pipeline GitHub Actions e stata creata ma non testata su un runner reale. Il primo push sara il test vero.

## Pattern Identificati

### Pattern positivi (da ripetere)
1. **Crescita test incrementale** — +4-5 test per story, conftest.py come base condivisa
2. **ruff come gate obbligatorio** — 0 errori prima di ogni commit
3. **Code review con AI** — trova bug reali (test che passano per motivo sbagliato)
4. **Story sequenziali con dipendenze chiare** — nessun conflitto o rollback

### Pattern da migliorare
1. **Verifica versioni dipendenze upfront** — evita downgrade e workaround
2. **Test che verificano la logica intesa** — non solo che passano
3. **File List completa fin dal primo commit** — non aggiunta in review
4. **Brownfield discovery budget** — allocare tempo per bug nascosti
